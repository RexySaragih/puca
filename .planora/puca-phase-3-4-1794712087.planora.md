# Púca Phase 3.4 Final Consolidation Native HTML Cache Workspace Jest

Plan profile: feature
Review status: in-review
Applicable domains: ui, backend, data, api, integrations, security, operations
Problem: Close Phase 3 with opt-in native static HTML reports, incremental disk cache, monorepo workspace sessions, and a single-worker Jest adapter, without scoped Stryker UI packages and without npm registry publish.
Users: Local Vitest developers (default unchanged); CI users wanting --html; monorepo and Jest-legacy maintainers opting into --workspace / --runner jest; maintainers auditing zero-Stryker-UI and GitHub-Release-only distribution.
Scope: Five ordered waves A HTML, B cache, C workspace, D Jest, E closeout. Spec: `.planora/puca-phase-3-4-technical-solution.md`. Roadmap: `.planora/puca-phase-3-technical_proposal.md`. Last Phase 3 slice (no 3.5).
Out of scope: npm publish OIDC optionalDependencies; @stryker-mutator/* scoped packages; CDN HTML assets; Jest multi-worker pool; Phase 3.5; always-on cache; storing mutated source on disk; changing A6 no-flag defaults.
Assumptions: Phases 1-3.3 locks stay; mutation-testing-report-schema retained for --json; ReportPort at src/application/ports/outbound/ReportPort.ts; Vitest-first; per-package .puca/cache.json under --workspace; jest workers soft-forced to 1.
Success criteria:
- SC-341: Given --html path, when session completes, then one self-contained HTML file exists with inline CSS/JS and SessionResult data, no @stryker-mutator/* and no network fetches in the artifact.
- SC-342: Given --cache, when two runs share unchanged sites, then .puca/cache.json stores status metadata only and the second run skips re-scoring those sites without writing mutated sources.
- SC-343: Given --runner jest on fixtures/jest-loop, when scored, then mutants run via RAM injection, workers are 1, and no sandbox dirs appear.
- SC-344: Given --workspace glob with multiple packages, when finished, then packages run sequentially and process exit is worst-of 2>1>0.
- SC-345: Given invalid --html or --runner or --workspace or --break-on-score or --sarif, when CLI starts, then exit 2.
- SC-346: Given no-flag puca, when run, then behavior matches Phase 1-3.3 defaults.
- SC-347: Given package.json and workflows, when audited, then no npm publish OIDC or git optionalDependencies were added in 3.4.
- SC-348: Given dependencies, when audited, then no @stryker-mutator/* scoped packages; mutation-testing-report-schema may remain for --json.
Risks: R23 HTML completeness; R24 cache false hits; R25 workspace false roots; R26 Jest module leak; R11 accidental publish.
Architecture decisions:
- ADR-034: Native self-contained HTML; ban scoped Stryker UI; keep JSON schema package.
- ADR-035: CachePort + FileHashCache metadata only; opt-in --cache.
- ADR-036: WorkspaceDiscoveryPort + sequential sessions; worst-of exit.
- ADR-037: JestTestRunner single-worker; soft force workers=1.
- ADR-038: Phase 3 distribution remains GitHub Releases only.
Delivery strategy: Wave A then B then C then D then E with strict Depends-on.
Backend — Service boundaries: HtmlFile/Sarif/Json/Stdio via ReportPort; FileHashCache via CachePort; WorkspaceTargetResolver + WorkspaceDiscoveryPort; JestTestRunner vs Vitest via createRuntime. Runtime: single session default; sequential multi-session under --workspace. Failure: invalid flags exit 2; missing jest exit 2; corrupt cache fail open; jest+workers>1 notice force 1.
Data — Entities: SessionResult embedded in HTML; cache entries keyed by composite hash; workspace package roots. Identity: site.id / hash keys. Validation: non-empty html/workspace paths; runner enum. Retention: .puca/cache.json and report paths are intentional writes; never mutated source in cache.
API — Consumers: human CLI; offline HTML readers; CI uploading sarif/json/html. Operations: --html --cache --workspace --runner plus prior flags. Outputs: terminal always; optional files. Errors: flag diagnostics on stderr. Compatibility: additive ports only.
Integrations — jest resolved from cwd; pnpm/npm/yarn workspace manifests; no GitHub API; no npm publish.
Security — Trust: user tests execute on purpose. Controls: no mutant sandbox dirs; no CDN in HTML; cache metadata only; sentinel before any new deps.
Operations — GitHub Releases only through Phase 3; Wave E greps enforce SC-347/348; docs closeout.
UI — Offline static HTML report only (not a hosted product site). Journeys: open --html file, filter by status, inspect file tree, read original vs replacement diffs. States: empty session, scored with mixed statuses. Accessibility: keyboard-usable filters, sufficient contrast (antislop-human). Visual: distinctive non-generic report chrome (frontend-design / minimalist-ui); no purple AI-slop defaults; no external font CDNs.
