# Púca Phase 3.2 Local Accuracy and File Summary

Plan profile: feature
Review status: in-review
Applicable domains: backend, data, api, security, operations
Problem: Local Vitest pre-commit runs still discover junk mutants inside template `${…}` interpolations, and the terminal only shows session-wide buckets so developers cannot scan per-file kill signal after a dirty-tree run.
Users: TypeScript/Vitest developers running `puca` before commit; maintainers proving SC-321..327 without changing distribution or the loop oracle.
Scope: Unconditional TemplateLiteral expression skip in puca-core; stdout File Summary table after Summary for scored runs; idle/refuse omit the block; PRODUCT/ARCHITECTURE/AGENTS/README sync. Spec: `.planora/puca-phase-3-2-technical-solution.md`. Roadmap: `.planora/puca-phase-3-technical_proposal.md`.
Out of scope: template opt-in flag; string-+ policy change; cache; Jest; monorepo; CI score gates; SARIF/HTML; npm publish; @puca scope; GHA/loader/tarball changes; ReportPort or domain Kill% types; adversarial fixtures; fixtures/loop oracle status changes.
Assumptions: Phases 1–3.1 A1–A26 stay; A27–A33 from the 3.2 technical solution; Kill% informational only; no new CLI flags; GitHub Release distribution unchanged.
Success criteria:
- SC-321: Given untagged `` `${a + b}` `` or `` `${flag}` ``, when discover runs, then those expressions yield 0 mutant sites.
- SC-322: Given tagged `` tag`${a + b}` ``, when discover runs, then the inner expression yields 0 mutant sites.
- SC-323: Given non-template `a + b`, when discover runs, then ArithmeticOperator site(s) still appear.
- SC-324: Given a scored run with statuses, when writeTerminal finishes, then stdout has Summary then File Summary with File|Total|Killed|Survived|Timeout|NoCov|Error|Kill% and Kill% rules from the spec.
- SC-325: Given idle exit 0 or pre-score refuse exit 2 with empty statuses, when writeTerminal finishes, then stdout has no File Summary block.
- SC-326: Given fixtures/loop oracle E2E, when puca runs, then statuses and exit code match the checked-in oracle.
- SC-327: Given lint:deps and parseArgs, when checked, then deps stay clean, no new CLI flags, and A6/exit locks are intact.
Risks: R18 TemplateLiteral override must not break non-template discovery; R19 empty statuses must omit File Summary; R1/R5/R6 unchanged.
Architecture decisions:
- ADR-029: Skip all TemplateLiteral expressions unconditionally; no CLI flag.
- ADR-030: File Summary is StdioReport presentation only; Kill% not domain; ReportPort unchanged.
Delivery strategy: Rust skip + tests → File Summary formatter + StdioReport → NAPI/E2E oracle lock → docs sync.
Backend — Service boundaries: OperatorVisitor in puca-core; StdioReport formats SessionResult; use case unchanged. Runtime: same session pipeline. Failure: A6 and exit codes unchanged; Kill% never refuses.
Data — Entities: existing Mutant/SessionResult only. Identity: site.id unchanged. Validation: none new. Retention: no .puca/cache.json; --json only intentional write.
API — Consumers: human CLI stdout/stderr. Operations: existing flags only. Outputs: UX-001 live stream + UX-004 File Summary; schema JSON unchanged. Errors: unchanged refuse paths. Compatibility: unpublished; no new flags.
Security — Trust: user tests still execute on purpose. Controls: mutants never on disk; no new loader or spawn surface.
Operations — npm run build / test / lint:deps / cargo test -p puca-core; no GHA or pack changes in this slice.
