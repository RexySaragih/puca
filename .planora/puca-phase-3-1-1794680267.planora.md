# Púca Phase 3.1 Prebuild Pipeline Without npm Publish

Plan profile: feature
Review status: in-review
Applicable domains: backend, data, api, integrations, security, operations
Problem: A rust-free host cannot run Púca because NAPI requires `npm run build`. This slice must pack platform tarballs, load `puca-<abi>` after local `.node` misses, and prove rust-free `fixtures/loop` oracle identity, without publishing to npm.
Users: Vitest/TS developers who will later install without rustc; maintainers who still source-build and run GHA.
Scope: Loader cascade in NapiMutatorEngine; napi.packageName puca; committed npm/<abi> stubs; files dist+schema; version 0.2.0; repository URL; public origin RexySaragih/puca on master; ci.yml two-job host smoke; release.yml v* matrix + GitHub Release tarballs; no registry. Spec: `.planora/puca-phase-3-1-technical-solution.md`.
Out of scope: npm publish; napi pre-publish; OIDC trusted publishing; git optionalDependencies; @puca scope; CI score gates; SARIF/HTML; disk cache; Jest; monorepo; template ${}; musl/linux-arm64; rename master to main; new CLI flags; A6/ADR-011/pool changes.
Assumptions: Phase 1 A1–A12 and Phase 2 A13–A18 stay; GHA Node 20; gh can create the public repo; fixtures/loop oracle is the smoke oracle; napi dirs are npm/<abi>/; tag v0.2.0 after merge; hostPlatformAbi unchanged; no new flags.
Success criteria:
- SC-301: Given no local .node and no puca-<abi>, when loadPucaBinding runs, then it throws UX-003 (names puca-<abi> and npm run build).
- SC-302: Given package-root puca-binding.<abi>.node, when loadPucaBinding runs, then discover/apply load.
- SC-303: Given only crates/puca-binding/puca-binding.<abi>.node, when loadPucaBinding runs, then it loads that file.
- SC-304: Given no local .node and puca-<abi> under that same root's node_modules, when loadPucaBinding(root) runs, then it loads via createRequire(root/package.json)("puca-"+abi).
- SC-305: Given npm pack of root, when the tarball is listed, then it has schema/ and zero .node files.
- SC-306: Given a packed platform stub with injected .node, when inspected, then it contains puca-binding.<abi>.node and os/cpu (libc on linux gnu).
- SC-307: Given PR macos-14 rust-free smoke, when puca runs cwd=fixtures/loop with --mutate src/**/*.ts --timeout 4000 --json, then exit 1 and statuses match oracle.statuses.json.
- SC-308: Given PR ubuntu-latest rust-free smoke, when the same command runs, then the same oracle match.
- SC-309: Given the smoke job, when which rustc runs, then it fails.
- SC-310: Given e2e missing-NAPI AC4, when CLI starts, then exit 2 and stderr matches UX-003.
- SC-311: Given git package.json, when inspected, then optionalDependencies is absent.
- SC-312: Given ci.yml and release.yml, when grepped, then npm publish, napi pre-publish, and NPM_TOKEN are absent.
- SC-313: Given tag darwin-x64 artifact, when file/otool runs, then it is x86_64 Mach-O.
- SC-314: Given Windows matrix job failure, when release.yml finishes, then the workflow is not failed for that reason.
- SC-315: Given tag v*, when GitHub Release exists, then it attaches puca-0.2.0.tgz plus gate platform tgzs (win32 only if that job succeeded).
- SC-316: Given no new flags, when puca runs as Phase 1+2, then targeting/exit/pool behavior is unchanged.
- SC-317: Given src/adapters/outbound/napi, when inspected, then NapiMutatorEngine/loadPucaBinding/bindingCandidatePaths/hostPlatformAbi remain the identifiers and bin is dist/cli.js.
Risks: R11 accidental registry publish (no publish steps); R12 file: in packed root (rejected); R13 @puca name (rejected); R14 A6 idle smoke (cwd+mutate glob); R15 rustc on PATH (separate job); R16 e2e AC4 must not symlink repo node_modules; R17 pack jobs must npm run build before npm pack; R6 missing addon exit 2.
Architecture decisions:
- ADR-020: Prebuild pipeline this cycle; npm registry still forbidden (amends ADR-006).
- ADR-021: napi.packageName puca; binaryName puca-binding; unscoped puca-<abi>.
- ADR-022: Filesystem .node then createRequire from root/package.json for puca-<abi>; throw; never process.exit.
- ADR-023: Packed root has zero .node; files are dist and schema.
- ADR-024: No optionalDependencies in git; smoke sibling-installs both tarballs.
- ADR-025: Two-job rust-free smoke; cwd fixtures/loop; oracle match.
- ADR-026: GHA artifacts only; no laptop or registry publish commands.
- ADR-027: v* GitHub Releases; Windows omit-if-failed.
- ADR-028: Origin https://github.com/RexySaragih/puca; branch master.
Delivery strategy: Origin → loader/UX-003 → manifests/stubs → pack identity tests → ci.yml → release.yml → docs.
Backend — Service boundaries: NapiMutatorEngine.loadPucaBinding is the only new runtime behavior; createRuntime/CLI mapping unchanged. Failure: miss or dlopen → throw UX-003 → runCli exit 2. No retry. No network fallback.
Data — Entities: platform package stubs, packed tgz artifacts, GitHub Release assets. Identity: abi string from hostPlatformAbi. Validation: os/cpu/libc on stubs. State: git version 0.2.0 unpublished. Retention: .node gitignored; tgz on GHA/Releases; no .puca/cache.json.
API — Consumers: CLI process; future npm clients (not this cycle). Operations: no new flags. Outputs: UX-003 stderr; packed tarball file lists. Errors: exit 2 on missing binding. Compatibility: unpublished; schemaVersion 2 still shipped in schema/.
Integrations — napi-rs build/artifacts; npm pack; GitHub Actions; GitHub Releases; gh origin. Timeouts: smoke uses --timeout 4000 matching e2e. Degradation: missing abi → UX-003; Windows job fail → omit tarball.
Security — Trust: CI-built .node; public Release assets accepted. Controls: no postinstall; no NPM_TOKEN; no process.exit in adapter; RAM mutants unchanged. Forbidden: @puca/*; CDN fetch; laptop npm publish.
Operations — Node 20 on GHA; rustc only on test/build jobs; smoke Node-only; master + v* triggers; rollback is git revert (nothing on npm).
